# دراسة تقنية مختصرة وشاملة لـ PaperCut NG/MF

هذه الدراسة مبنية على المعلومات العامة المتاحة في وثائق PaperCut الرسمية والمواد الفنية المنشورة علنًا. الهدف منها ليس نسخ PaperCut، بل فهم نمط النظام المطلوب لبناء **Extreme Print Management System** بطريقة واقعية وقابلة للتوسع.

## 1. ما هو PaperCut؟

PaperCut هو نظام إدارة طباعة مؤسسي. أشهر نسختين في البيئة التقليدية هما:

- **PaperCut NG**: إدارة طباعة على مستوى الشبكة: تتبع، حصص، قواعد، تقارير، تكلفة.
- **PaperCut MF**: نفس قاعدة NG تقريبًا، مع تكامل أعمق مع أجهزة MFD/MFP متعددة الوظائف للتحكم في الطباعة والنسخ والمسح والفاكس من شاشة الجهاز نفسها.

الفكرة الأساسية: لا يرسل المستخدمون الطباعة مباشرة بدون رقابة. كل مهمة تمر عبر طبقة مراقبة تستطيع:

- معرفة المستخدم والطابعة والصفحات والنسخ واللون والدوبلكس.
- حساب التكلفة.
- خصم الرصيد أو الحصة.
- حجز المهمة حتى يطلقها المستخدم من الطابعة.
- رفض المهمة إذا خالفت سياسة المؤسسة.
- تسجيل كل شيء للتقارير والتدقيق.

## 2. المكونات الرئيسية في PaperCut

### 2.1 Application Server

الخادم المركزي المسؤول عن:

- قاعدة البيانات.
- لوحة تحكم الإدارة.
- واجهة المستخدم النهائية.
- قواعد التسعير والحصص.
- المستخدمين والمجموعات والحسابات المشتركة.
- التقارير والسجلات.
- API/خدمات الويب التي تتواصل معها باقي المكونات.

في PaperCut عادة يكون الاتصال بين المكونات بخدمات ويب عبر HTTP/HTTPS، تاريخيًا XML/SOAP، مع منافذ شائعة مثل 9191/9192/9195 حسب الإعداد.

### 2.2 Print Provider

خدمة تثبت على خادم الطباعة أو الجهاز الذي يستضيف الطوابير. وظيفتها:

- مراقبة spooler أو نظام الطباعة المحلي.
- التقاط بيانات المهمة قبل/أثناء الطباعة.
- إرسال بيانات المهمة للخادم المركزي.
- تنفيذ قرار الخادم: طباعة، حجز، رفض، أو تعليق.

هذه الخدمة مهمة في بيئات Windows Print Server وmacOS وLinux/CUPS.

### 2.3 Secondary Print Server

عندما توجد عدة خوادم طباعة، يكون واحد منها هو الخادم الأساسي الذي يعمل عليه Application Server، والبقية تعمل كخوادم ثانوية عليها Print Provider فقط. كل خادم ثانوي يرسل الأحداث والمهام للخادم الأساسي.

### 2.4 Direct Print Monitor

عندما يطبع المستخدم مباشرة من جهازه إلى الطابعة بدون Print Server، يتم تثبيت مراقب صغير على جهاز المستخدم. وظيفته شبيهة بـ Print Provider لكنه يعمل على جهاز المستخدم:

- يراقب الطوابير المحلية.
- يرسل job metadata للخادم.
- يربط الطابعات المتشابهة في تقارير موحدة.

ملاحظة مهمة في PaperCut: Direct Print Monitor لا يثبت عادة على نفس الجهاز الذي عليه Print Provider.

### 2.5 User Client

برنامج اختياري يظهر للمستخدم:

- الرصيد الحالي.
- تحذيرات انخفاض الرصيد.
- نافذة تأكيد قبل الطباعة.
- اختيار الحساب/القسم/المشروع الذي ستحمل عليه التكلفة.
- طلب تسجيل دخول عند الطباعة من أجهزة غير موثوقة أو غير منضمة للدومين.

المراقبة نفسها في PaperCut غالبًا server-side؛ User Client ليس شرطًا لكل تتبع، لكنه ضروري عند الحاجة لتفاعل المستخدم.

### 2.6 Site Server

خادم فرعي يستخدم في الفروع أو المواقع البعيدة. وظيفته:

- تخزين نسخة مؤقتة من بيانات الخادم المركزي.
- استقبال طلبات Print Providers وMFDs محليًا عند انقطاع الاتصال.
- مزامنة السجلات والعمليات عند عودة الاتصال.

هذا مهم لاستمرارية الطباعة في المؤسسات متعددة الفروع.

### 2.7 Embedded MFD App

في PaperCut MF، يوجد تطبيق يثبت داخل جهاز الطابعة/الناسخة متعددة الوظائف. هذا التطبيق يعمل على منصة الشركة المصنعة، مثل:

| الشركة | منصة التكامل الشائعة |
| --- | --- |
| HP | OXP / Workpath / FutureSmart |
| Canon | MEAP |
| Ricoh | SmartSDK / SOP |
| Xerox | EIP |
| Sharp | OSA |
| Konica Minolta | OpenAPI / i-Option |
| Toshiba | e-BRIDGE Open Platform |
| Kyocera | HyPAS |
| Lexmark | eSF |
| Epson | Open Connect |

وظائف التطبيق المدمج:

- تسجيل دخول المستخدم من شاشة الطابعة.
- قراءة بطاقة/Badge أو PIN.
- عرض المهام المحجوزة للمستخدم.
- إطلاق مهمة محددة أو كل المهام.
- التحكم في النسخ والمسح والفاكس.
- اختيار الحساب أو المشروع.
- إرسال سجلات الاستخدام للخادم.

## 3. هل يمكن تثبيت برنامج واحد داخل جميع الطابعات؟

لا يوجد عمليًا برنامج واحد يعمل داخل **كل** الطابعات. السبب:

- كل شركة لديها SDK ومنصة تشغيل مختلفة.
- بعض الطابعات ليست MFD ولا تسمح بتثبيت تطبيق داخلي.
- بعض الأجهزة لا تحتوي شاشة أو مساحة تخزين أو منصة تطبيقات.
- بعض الشركات تتطلب اعتمادًا رسميًا أو شهادات أو شراكة.
- بعض التكاملات تعمل عبر بروتوكولات خارجية فقط مثل IPP/SNMP/PJL وليس تطبيقًا داخليًا.

الحل الصحيح هو طبقة **Vendor Adapter**:

1. **Embedded Adapter** للأجهزة الذكية التي تقبل تطبيقًا داخليًا.
2. **Network Gateway Adapter** للطابعات التي لا تقبل تطبيقًا داخليًا، عبر خادم طباعة أو جهاز وسيط.
3. **CUPS/Windows Print Provider Adapter** لمراقبة الطوابير من الخادم.
4. **Direct Client Monitor Adapter** للطباعة المباشرة من أجهزة المستخدمين.

بهذا تحصل المؤسسة على تجربة موحدة حتى لو اختلفت طريقة التكامل تحت السطح.

## 4. تدفق الطباعة النموذجي

### 4.1 طباعة عادية عبر Print Server

1. المستخدم يرسل المستند إلى طابعة مشتركة.
2. Print Provider يلتقط المهمة من spooler.
3. يرسل metadata للخادم: المستخدم، الطابعة، الصفحات، اللون، النسخ، اسم المستند.
4. الخادم يحسب التكلفة ويفحص الحصة والسياسات.
5. القرار:
   - طباعة وخصم.
   - حجز حتى الإطلاق.
   - رفض.
6. تسجل العملية في قاعدة البيانات والتقارير.

### 4.2 Secure / Find-Me Print

1. المستخدم يرسل المهمة إلى طابور عام.
2. المهمة تبقى held.
3. المستخدم يذهب لأي جهاز مدعوم.
4. يسجل الدخول بالبطاقة أو PIN أو اسم المستخدم.
5. التطبيق المدمج يعرض مهامه.
6. يختار Release.
7. الخادم يسمح بالطباعة على الجهاز الحالي ويخصم التكلفة.

### 4.3 Direct Print

1. المستخدم يطبع مباشرة إلى IP الطابعة.
2. Client/Direct Monitor على جهاز المستخدم يرسل بيانات المهمة للخادم.
3. الخادم يطبق السياسات.
4. حسب قدرة نظام التشغيل والطابعة، يتم السماح أو الحجز أو التسجيل أو الرفض.

## 5. الوظائف الأساسية في PaperCut

- إدارة المستخدمين والمجموعات.
- التكامل مع AD/LDAP/Azure/Google حسب المنتج والإعداد.
- حصص مالية أو عدد صفحات.
- إعادة تعبئة الحصص يوميًا/أسبوعيًا/شهريًا/فصليًا.
- أرصدة قابلة للتراكم أو غير قابلة للتراكم.
- Overdraft محدود.
- تكلفة مختلفة حسب الطابعة، اللون، الحجم، الدوبلكس، نوع الورق.
- حسابات مشتركة للجهات أو الأقسام أو المشاريع.
- قواعد طباعة: منع اللون، إجبار duplex، منع مهام كبيرة، تحذير عند طباعة email.
- Hold/Release وFind-Me printing.
- Web Print وMobility Print وPrint Deploy في منتجات PaperCut الحديثة.
- تقارير جاهزة وسجلات تدقيق.
- أرشفة أو حذف سجلات قديمة للحفاظ على الأداء.

## 6. قاعدة البيانات والتقارير

PaperCut يستخدم قاعدة داخلية في التثبيت الافتراضي، ويمكن التوسع إلى RDBMS خارجي مثل PostgreSQL أو SQL Server أو MySQL أو Oracle في البيئات الأكبر.

متطلبات Extreme المقترحة:

- SQLite للنسخ الصغيرة أو التجريبية.
- PostgreSQL للإنتاج.
- جداول منفصلة: users, groups, printers, jobs, transactions, accounts, policies, audit_logs, devices, agents.
- سجلات immutable للعمليات المالية والطباعة.
- تقارير read-only لا تعدل البيانات التشغيلية.

## 7. الأمن

نقاط يجب تطبيقها في Extreme:

- HTTPS/TLS بين كل المكونات.
- تسجيل agents بمفاتيح أو شهادات.
- صلاحيات RBAC للإدارة.
- فصل أدوار: Admin, Helpdesk, Auditor, Printer Operator, End User.
- منع تعديل سجلات التكلفة بعد إنشائها.
- Audit log لكل تغيير إداري.
- إخفاء أو تشفير أسماء المستندات حسب سياسة الخصوصية.
- دعم retention policy لحذف/إخفاء السجلات القديمة.

## 8. خريطة بناء Extreme Print Management System

### المرحلة الحالية في هذا المستودع

- Server MVP بواجهة ويب وSQLite.
- قواعد تكلفة وحصص.
- حفظ print jobs وtransactions.
- Release/Deny للمهام المحجوزة.
- Tests للنواة.

### المطلوب للوصول إلى منتج شبيه PaperCut

1. **Extreme Server**
   - API موحد.
   - إدارة المستخدمين والطابعات والسياسات.
   - تقارير وسجلات تدقيق.
   - قاعدة إنتاجية.

2. **Extreme Client Agent**
   - يعمل على Windows/macOS/Linux.
   - يعرض الرصيد والتنبيهات.
   - يراقب الطباعة المباشرة.
   - يطلب اختيار account أو تأكيد المستخدم.

3. **Extreme Print Provider**
   - يعمل على Windows Print Server وLinux CUPS.
   - يراقب spooler.
   - يرسل job events.
   - ينفذ hold/release/deny.

4. **Extreme Printer Controller**
   - طبقة adapters:
     - HP OXP/Workpath.
     - Canon MEAP.
     - Ricoh SmartSDK.
     - Xerox EIP.
     - Sharp OSA.
     - Konica Minolta OpenAPI.
     - Toshiba e-BRIDGE.
     - Kyocera HyPAS.
     - Lexmark eSF.
     - Epson Open Connect.
   - للأجهزة غير الداعمة: gateway خارجي أو release station.

5. **Extreme Site Server**
   - كاش محلي.
   - Offline mode.
   - مزامنة لاحقة.

## 9. خلاصة مهمة

لبناء نظام مثل PaperCut يجب تصميمه كمنظومة موزعة، وليس كتطبيق واحد. لا يمكن ضمان تطبيق داخلي واحد لكل الطابعات، لكن يمكن ضمان تجربة موحدة عبر adapters متعددة. النسخة العملية الأولى يجب أن تدعم:

- Server.
- Client Agent.
- Print Provider / Printer Gateway.
- Embedded Adapter Interface.

ثم تتم إضافة كل شركة طابعات كتكامل مستقل حسب SDK والاعتماد المطلوب.
