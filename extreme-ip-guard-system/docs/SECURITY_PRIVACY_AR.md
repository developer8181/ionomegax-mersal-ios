# ضوابط الأمن والخصوصية في Extreme IP Guard

## الهدف

أي نظام شبيه بـ IP Guard يمكن أن يكون قوياً وحساساً في الوقت نفسه. لذلك يجب
بناء Extreme IP Guard كمنصة دفاعية شفافة، لا كأداة مراقبة سرية. هذه الوثيقة
تحدد الضوابط التي تجعل النظام مناسباً للمؤسسات وتحمي المستخدمين والمؤسسة معاً.

## ما يجب فعله

- نشر النظام فقط على أجهزة تملكها المؤسسة أو لديها تصريح واضح لإدارتها.
- تقديم إشعار واضح للمستخدمين عن أنواع البيانات التي تجمع والغرض منها.
- تفعيل RBAC بحيث لا يستطيع أي مسؤول رؤية كل شيء بلا سبب.
- تسجيل كل إجراء إداري في Audit Log.
- استخدام MFA لحسابات الإدارة.
- تشفير الاتصالات بين الوكلاء والخادم.
- توقيع الوكلاء والتحقق من سلامة التحديثات.
- ضبط سياسات احتفاظ مختلفة حسب حساسية الحدث.
- استخدام الموافقات المتعددة لعزل الأجهزة أو تصدير التقارير الحساسة.
- إخفاء أو تقليل البيانات الشخصية في الواجهات والتقارير.

## ما يجب تجنبه

- التسجيل الخفي للمفاتيح أو الشاشة.
- جمع كلمات المرور أو الرموز السرية.
- تجاوز صلاحيات النظام أو تعطيل أدوات الحماية.
- اعتراض الاتصالات دون تصريح قانوني واضح.
- تخزين محتوى الملفات الحساسة عندما تكفي البصمات أو الميتاداتا.
- منح مسؤولي النظام صلاحيات غير محدودة دون تدقيق.
- الاحتفاظ بالأحداث إلى أجل غير مسمى.

## نموذج الصلاحيات المقترح

| الدور | الصلاحيات |
| --- | --- |
| Security Viewer | قراءة لوحات المعلومات والأحداث المخفية جزئياً |
| Security Analyst | التحقيق في الأحداث وطلب إجراءات |
| Security Admin | إدارة السياسات والاستجابة |
| Privacy Officer | مراجعة الوصول للبيانات الشخصية والتصدير |
| Auditor | قراءة سجلات التدقيق فقط |
| Break Glass Admin | صلاحية طوارئ مؤقتة ومراقبة بشدة |

## الاحتفاظ بالبيانات

| نوع البيانات | احتفاظ مقترح |
| --- | --- |
| Heartbeat للأصول | قصير إلى متوسط حسب المتطلبات |
| أحداث DLP منخفضة | قصير |
| أحداث DLP عالية/حرجة | متوسط مع مراجعة |
| سجلات التدقيق | أطول حسب الامتثال |
| محتوى الملفات | تجنبه افتراضياً |

## آلية الموافقة

بعض القرارات يجب ألا تكون آلية بالكامل:

- عزل جهاز مدير تنفيذي أو خادم إنتاج.
- تصدير تقارير تحتوي بيانات شخصية.
- تغيير سياسة DLP عامة.
- تعطيل سياسة حماية.
- فتح استثناء طويل الأمد.

## متطلبات الإنتاج الأمنية

- SSO مع MFA.
- تشفير at-rest وin-transit.
- مفاتيح managed KMS.
- Secrets Manager بدلاً من متغيرات نصية مكشوفة.
- Rate limiting للـ API.
- حماية CSRF وCORS مضبوط.
- فصل بيئات التطوير والاختبار والإنتاج.
- نسخ احتياطي مشفر ومجرب.
- مراقبة سلامة قاعدة البيانات وسجلات التدقيق.

## مبدأ التصميم

القوة الحقيقية ليست في جمع كل شيء، بل في جمع الحد الأدنى الصحيح، اتخاذ قرار
واضح قابل للتفسير، وترك أثر تدقيق لا يمكن إنكاره.
